# git-purge-history.sh

交互式地从 Git 全部历史中移除指定的文件 / 目录（密钥、大文件等），其余文件的提交历史保持不变。

## 功能说明

适用场景：不小心把 `.env`、`id_rsa`、证书私钥等敏感文件，或体积过大的二进制文件提交进了仓库，需要把它们从**所有历史提交**中彻底抹除，而不仅仅是从当前版本删除。

核心特性：

- **交互式菜单**：扫描历史中体积最大的文件、按关键字搜索历史文件名、手动输入路径，三种方式挑选目标。
- **通配符支持**：路径支持 `*`、`?` 等通配符，例如 `config/*.key`。
- **优先使用 `git-filter-repo`**（官方推荐工具，速度快、更安全），未安装时自动回退到 `git filter-branch`。
- **自动备份**：重写历史前先创建完整的 bundle 备份，失败可随时恢复。
- **远程自动恢复**：`filter-repo` 会移除 remote 配置，脚本会在重写后自动恢复原有远程地址。
- **执行后校验**：逐条确认目标路径已从历史中清除，并提示强制推送、密钥轮换等后续步骤。

## 环境要求

- `bash` 4+
- `git`
- 当前目录必须在 Git 仓库内，且仓库至少有一个提交
- 推荐安装 `git-filter-repo`（`pip install git-filter-repo`），否则回退到较慢的 `git filter-branch`
- 工作区与暂存区需保持干净（未跟踪文件不受影响）

## 用法

```bash
./git-purge-history.sh                 # 纯交互模式
./git-purge-history.sh .env secrets/   # 预先指定要移除的路径，再进入菜单
./git-purge-history.sh -h              # 查看帮助
```

命令行传入的路径会先加入移除列表，然后仍进入交互菜单，可以继续补充、预览、执行。

路径一律**相对仓库根目录**（脚本会自动 `cd` 到仓库根），支持目录与通配符。

## 交互菜单

| 选项 | 功能 | 说明 |
| --- | --- | --- |
| `1` | 扫描历史中最大的文件 | 列出所有分支/标签历史中体积最大的前 N 个文件（默认 20），按编号挑选加入移除列表 |
| `2` | 按文件名关键字搜索 | 在全部历史出现过的文件路径中搜索关键字（不区分大小写，如 `.env`、`id_rsa`、`.pem`），按编号挑选 |
| `3` | 手动输入路径 | 逐行输入文件或目录，支持通配符如 `config/*.key`，空行结束 |
| `4` | 查看 / 修改已选列表 | 按编号删除某些项，或 `c` 清空全部 |
| `5` | 预览影响范围 | 显示每个路径在历史中涉及的提交数；路径当前仍被跟踪时会提示重写后工作区文件会被删除；历史中找不到时提示检查写法 |
| `6` | 备份并执行移除 | 确认后备份 → 重写历史 → 恢复远程 → 校验 → 询问是否强制推送 |
| `0` | 退出 | 不做任何修改 |

挑选时的编号语法：`1 3 5`（多个）、`a`（全部）、回车跳过。

## 示例

交互式清理误提交的密钥文件：

```bash
./git-purge-history.sh
# 菜单选 2，输入关键字 id_rsa，按编号挑选
# 菜单选 5 预览影响
# 菜单选 6 执行移除，输入 yes 确认
```

直接指定路径执行：

```bash
./git-purge-history.sh .env config/jwt.key
```

移除一批同格式的证书私钥（通配符）：

```bash
./git-purge-history.sh 'certs/*.pem'
```

清理历史中的大文件（如误提交的压缩包）：

```bash
./git-purge-history.sh
# 菜单选 1 查看体积最大的文件，挑选 dist.tar.gz 等
```

## 执行流程（选项 6）

1. 检查工作区是否干净，有未提交修改则中止。
2. 展示移除列表与预览，要求输入 `yes` 确认。
3. 创建完整备份 bundle：`../<仓库名>-backup-<时间戳>.bundle`。
4. 若目标文件当前仍被跟踪，把当前工作区副本另存为 `../<仓库名>-keep-<时间戳>.tar`（重写后工作区的这些文件会被删除）。
5. 记录现有 remote 配置。
6. 重写历史：
   - 有 `git-filter-repo` 时：`git filter-repo --force --invert-paths --path ...`（通配符用 `--path-glob`）。
   - 否则：`git filter-branch --index-filter 'git rm -r --cached --ignore-unmatch ...' --prune-empty --tag-name-filter cat -- --all`，随后清理 `refs/original/`、过期 reflog 并执行 `git gc --prune=now --aggressive`。
7. 重新添加被 `filter-repo` 移除的 remote。
8. 校验：逐个路径统计历史涉及提交数，确认归零。
9. 询问是否立即对每个远程执行 `git push --force --all && git push --force --tags`。
10. 打印后续必做事项（见下文）。

## 恢复备份

重写失败或想回退时，从备份 bundle 克隆即可找回旧历史：

```bash
git clone '/path/to/repo-backup-<时间戳>.bundle' restored-repo
```

若只需找回被删除文件的最新版本，解包 keep 备份：

```bash
tar -xf '/path/to/repo-keep-<时间戳>.tar'
```

## 执行后必做事项

1. **密钥泄露**：移除的是密钥/令牌时，只要曾经推送过，就应视为已泄露，立刻到对应平台吊销并轮换。
2. **强制推送**：未在脚本内推送时，手动执行 `git push <remote> --force --all && git push <remote> --force --tags`。
3. **通知协作者**：删除旧本地仓库后重新 clone，不要 pull/merge，否则旧历史会被带回来。
4. **平台残留**：GitHub/GitLab 上的旧 PR 引用、缓存视图、fork 里仍可能保留旧对象，需联系平台支持清理（GitHub: Support → 移除敏感数据）。
5. **防止再犯**：把这些路径加入 `.gitignore`。

## 常见问题

预览时提示「历史中没有找到该路径」。
路径区分大小写且必须相对仓库根目录；目录不要带多余的 `./` 前缀（脚本会自动去掉）。可用菜单选项 2 按关键字搜索确认实际路径写法。

执行被中止，提示工作区有未提交的修改。
先提交或 `git stash`，再重试。未跟踪文件不受影响，无需处理。

`filter-repo` 执行后远程地址不见了。
这是 `git-filter-repo` 的默认行为（避免误推），脚本会自动恢复 remote；若手动执行过 `filter-repo`，用 `git remote add <name> <url>` 加回即可。

校验时提示某路径「仍有 N 个提交涉及」。
通常是 `refs/stash` 等其他引用仍指向旧提交，执行 `git stash clear` 或对相应引用做清理后重试。

强制推送被拒绝。
远程分支可能受保护，需先在平台上临时关闭保护再推。

只想从当前版本删除文件、不动历史。
不需要本脚本，直接 `git rm --cached <path>` 并提交即可；本脚本用于**彻底清除全部历史记录**。
